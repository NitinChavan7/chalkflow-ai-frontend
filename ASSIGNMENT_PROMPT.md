Document the intended learner, problem, design choices, setup, environment variable names with placeholders, live versus mocked behavior, trade-offs, limitations and future improvements. Confirm that both frontend and backend source will be accessible to reviewers.

Prepare a concrete submission checklist for the repository URL, public demo URL and Braynix submission form. Do not claim a repository or demo is public, deploy, send messages, or submit the form without the actual available links and explicit authorization as appropriate.
